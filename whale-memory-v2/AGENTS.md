# AGENTS.md

给 AI 的常驻上下文。开工前读完。

## 必读顺序

1. `docs/README.md` —— 文档导航
2. `docs/PRD.md` —— 做什么、不做什么、验收标准
3. `docs/设计文档.md` —— 架构、数据模型、算法口径
4. `docs/数据契约.md` —— 字段、状态机、工具接口
5. `docs/任务清单.md` —— 当前该做哪个任务

`调研笔记.md` 是阅读记录，**不是规格**。冲突时以 `docs/` 为准。

## 完成定义（DoD）

一个任务算完成，必须同时满足：

1. 代码提交，`npm run check && npm test` 全绿
2. 对应验收用例（`docs/PRD.md` §2）有测试且通过
3. 如果改了架构，`docs/` 已同步更新
4. 任务清单里该任务勾选完成

**「看起来对」不算完成。** 没有验收用例的任务不许标记完成。

## 验证命令

```bash
npm run check         # lint + typecheck，必须通过
npm test              # 单测，必须通过
npm run test:accept   # 验收用例，必须通过
```

提交前三条都要跑绿。

## 禁止事项

1. **不物理删除任何记忆条目**。只能改状态。
2. **不修改 `原文/` 下的文件**。那是只追加的资产。
3. **不在文档里写变更记录**（「本次新增」「v2 加了」）。改就改，文档只呈现最终形态。
4. **不在文档里写实测数字和过程叙述**。那属于 `调研笔记.md`。
5. **不新增运行时依赖**，除非在 PR 说明里写清理由并经确认。
6. **不提交密钥、token、密码**。测试用 `.env.example` 和模拟数据。
7. **不把模型推断写成 `active`**。推断只能进 `candidate`。
8. **不在定时器回调里让异常冒出去**。全部 `try/catch`。
9. **不按 UTF-16 单元截断文本**。按码点。
10. **不改公共接口**（`docs/数据契约.md` §3 的工具签名）而不改文档。
11. **不假装成功**。写入是否成功只看显式的 `committed` 状态；没有确认就是没写成。
12. **不跳过校准试验**（`docs/PRD.md` §2.1）。先证明验收能认出破坏，再拿它验收。
13. **不挤掉常驻层已有条目**。常驻层满了就拒绝新写入（`layer_full`），不替换、不降级。
14. **不省略新鲜度提示**。时间敏感条目注入时必须带「请先核实」。
15. **不直接调 `Date.now()`**。时间从注入的时钟取，否则测试无法复现。
16. **写入未落盘不返回成功**。`ok: true` 只表示落盘完成。

## 子代理与文档

- 子代理**不得修改 `docs/`**，只能提建议
- 主代理决定是否落入文档
- 写代码与改文档分开做，不同时进行

## 关键约束速记

| 约束 | 值 |
|---|---|
| 记忆层级 | 全局一份，不按项目分库 |
| 项目归属 | 字段标记 + 检索加权 |
| 原文 | 永久保留 |
| 条目状态 | 六种，不可物理删除 |
| 重要度 / 可信度 | 两条独立轴（α / β） |
| 注入通道 | 变化走 context，固定走 section |
| 过期处理 | 压缩 + 归档，不删 |
