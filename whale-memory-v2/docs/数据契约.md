# whale-memory-v2 · 数据契约

> 本文定义**数据结构与工具接口**。字段含义、类型、约束以本文为准。
> 实现细节（函数签名、内部结构）不在此描述。

---

## 1. 文件布局

```
<DSH_HOME>/whale-memory-v2/
  记忆.json               投影层：全部条目的当前视图
  原文/YYYY-MM.jsonl      原始素材，append-only
  备份/events-*.json.gz   带 sha256 的备份包
  状态.json               运行状态：游标、配额、上次维护时间
```

**约束**

- `原文/` 只追加，不修改、不删除
- `记忆.json` 可由 `原文/` 重建
- 所有文件 UTF-8 无 BOM
- 写文件先写临时文件再原子替换

## 2. 记忆条目

### 2.1 完整字段

```jsonc
{
  "id": "string",              // 必填，唯一。格式 m_<YYYYMMDD>_<序号>
  "text": "string",            // 必填，≤600 字。一条只装一件事
  "layer": "user|project|knowledge|working",  // 必填
  "project": "string",         // 必填，默认 "全局"
  "status": "candidate|active|contested|superseded|invalidated|archived",

  "alpha": 0.5,                // 必填，[0,1]，重要度
  "beta": 0.7,                 // 必填，[-1,1]，可信度
  "evidence": "explicit|engage|passive",  // 必填
  "counterEvidence": [],       // 反驳证据条目 id 列表

  "encodings": [0],            // 编码时间戳数组，创建 + 每次被用到
  "lastHit": 0,                // 最后一次被用到的时间
  "hits": 0,                   // 被用到次数

  "summary": "string",          // 必填，≤60 字。判断相关性用，正文才是交付
  "keywords": [],              // 必填，5–12 个
  "factKey": "string|null",    // 同键只留最新。不写具体值
  "supersedes": "string|null", // 取代了哪条
  "supersededAt": "number|null",
  "invalidatedBy": "string|null",

  "createdAt": 0,
  "source": "explicit|model|import",
  "sourceRef": "原文库位置，必填",   // 月份分片 + 行号
  "sourceMissing": false,      // 原文被人工删除后置 true
  "schemaVersion": 1
}
```

### 2.2 字段规则

| 字段 | 规则 |
|---|---|
| `text` | ≤600 字；超过则拒绝写入 |
| `alpha` | 1.0 = 每轮必挂；0.5 = 默认；0 = 可忽略 |
| `beta` | 1.0 = 用户明说；0.7 = 默认；0 = 玩笑/猜测；<0 = 不可信 |
| `factKey` | 「对象.方面」，不得包含具体值 |
| `summary` | 判断相关性用。模型没给时取正文首句，≤60 字 |
| `keywords` | 用于检索召回，不含标点 |
| `sourceRef` | 原文库中的位置（分片 + 行号），写入时生成，之后不改 |
| `supersededAt` | 只在 `status=superseded` 时有值 |
| `encodings` | 创建时写入一次；每次被检索命中且确认有效时追加 |

### 2.3 状态转移

```
candidate  → active        证据足够（见 PRD A1/A2）
candidate  → archived      超期未晋升
active     → superseded    写入同 factKey 的新条目
active     → invalidated   用户明确纠正
active     → contested     出现反驳证据且不可消解
active     → archived      超过淘汰期限
contested  → active        冲突消解（时间/条件限定）
contested  → superseded    被新版本取代
任意        → 不可物理删除
```

**不变式**

1. 任何条目不得物理删除
2. `superseded` / `invalidated` 不得出现在注入结果中
3. `candidate` 不得出现在注入结果中
4. `archived` 可检索，不注入

## 3. 工具接口

### 3.1 `remember`

```jsonc
// 入参
{
  "text": "string",                    // 必填
  "layer": "user|project|knowledge|working",  // 默认 user
  "project": "string",                 // 默认「全局」
  "alpha": "number",                   // 默认 0.5
  "beta": "number",                    // 默认 0.7
  "keywords": ["string"],              // 默认由 text 抽取
  "factKey": "string",                 // 可选
  "supersedes": "string",              // 可选，旧条目 id 或大意
  "quote": "string",                   // 可选，要记的原话片段
  "quoteSource": "string",             // 给了 quote 就必须给，且 quote 必须是它的子串
  "at": "string",                      // 可选，这件事**什么时候发生的**（ISO 或 YYYY-MM-DD）
  "source": "explicit|model|import"    // 默认 explicit；model 一律进 candidate
}

// 出参
{ "ok": true, "id": "m_...", "status": "active|candidate" }
```

**`at` 的规矩**：`createdAt` 记的是「这件事什么时候发生的」，不是「什么时候写进来的」。

- 不给 → 用写入时刻（旧行为）
- 给了 → 用它做 `createdAt`，注入的相对时间、压缩计时都跟着它走
- 明显在未来的 `at` 会被拒（`invalid_time`）—— 多半是把秒当成了毫秒

**为什么必须有**：流水线整理历史会话时，如果一律用写入时刻，用户那天说「明天去杭州」
会被记成「整理当天的记忆里说：明天去杭州」。时间线全错，压缩也会把老记忆当成新的。

**quote 的规矩**：引用原话不能是编的。

- 只给 `quote` 不给 `quoteSource` → 拒收（`quote_unverifiable`），因为没法验证
- `quote` 不是 `quoteSource` 的子串 → 拒收（`quote_mismatch`）
- 两者都不给 → 正常写入，条目 `quote` 为 `null`

这条规则的目的是拦住「编一句用户没说过的话当引用」——那比编事实更隐蔽。

失败：`{ "ok": false, "error": "code", "text": "原因" }`

### 3.2 `search`

```jsonc
// 入参（两种模式）
{ "query": "string", "limit": 8, "layer": "string", "project": "string" }
{ }   // 不带 query = 返回索引概览

// 出参（查询模式）
{ "ok": true, "hits": [
  { "id": "...", "summary": "...", "at": 0, "status": "active", "alpha": 0.9 }
]}

// 出参（概览模式）
{ "ok": true, "index": {
  "total": 0, "byLayer": {}, "byStatus": {},
  "oldestAt": 0, "newestAt": 0,
  "hint": "怎么查：给关键词、给时间范围、或按 id 读原文"
}}
```

默认返回**摘要**，不返回正文。要正文用 `recall`。

#### 时光机（`asOf`）

```jsonc
{ "query": "方案", "asOf": "2026-10-10" }   // 查那一刻有效的事实
```

给了 `asOf` 就**不看当前状态，只看那一刻是否有效**：

- `createdAt > asOf` → 那时还没产生，排除
- `supersededAt <= asOf` → 那时已被取代，排除
- `invalidatedAt <= asOf` → 那时已作废，排除
- 其余保留（`archived` 没有时间戳，视为一直有效——归档是「不再注入」，不是「当时就不成立」）

出参会回显 `asOf` / `asOfText`，免得调用方把它当成「现在」的结果。

**用途**：回答「上周定的是什么方案」——即使后来被改了，也能看到当时为真的版本。

**和普通检索的差别**：普通检索会**翻到**被取代的条目（带 `status` 标注），
`asOf` 是**筛掉**那些当时已失效的。两者是互补的：一个说「它现在怎样」，一个说「它那时怎样」。

### 3.3 `update`

```jsonc
{ "id": "string", "text": "string", "alpha": "number", "beta": "number",
  "status": "active|archived|invalidated", "keywords": ["string"] }
```

### 3.4 `forget`

```jsonc
{ "id": "string", "reason": "string" }   // 只改状态为 invalidated/archived，不删
```

### 3.5 `recall`

按 id 取原文或正文。用于「翻到出处」。

```jsonc
// 入参
{ "id": "string", "offset": 0, "limit": 2000 }

// 出参
{ "ok": true, "id": "...", "text": "...", "at": 0,
  "sourceRef": "...", "source": "原文片段或 null",
  "sourceMissing": false, "offset": 0, "nextOffset": null, "totalChars": 0 }
```

`sourceMissing=true` 表示原文已被人工删除，条目本身仍返回。

### 3.6 `maintain`

把「很久没被提起」的条目压深一级。**低频操作，显式触发**——不挂在每次写入后面。

```jsonc
// 入参
{ "dryRun": false }

// 出参
{ "ok": true, "changed": 1, "pending": 0, "dryRun": false,
  "items": [ { "id": "...", "from": 0, "to": 1 } ] }   // 明细最多 20 条
```

- `changed`：压缩等级真的变了的条数
- `pending`：没固化、只被标记的条数（不压缩）
- `items`：只回前 20 条，结果每轮会被重发，不吐整库
- `dryRun=true`：只算计划，不写盘

压缩等级 0→4，到顶也只是「只剩一行目录」，条目不物理删除。

### 3.7 `digest`

把最近几天「用户说过的话」捞出来，用来补记漏掉的记忆。

```jsonc
// 入参
{ "days": 7, "limit": 60 }

// 出参（成功）
{ "ok": true, "count": 60, "text": "..." }   // text 是人读的列表，直接给模型

// 出参（失败）
{ "ok": false, "error": "sessions_dir_missing", "text": "找不到会话目录" }
```

- 只返回 `user/message`；助手自己说的话不算外部事实
- 返回前先脱敏，密码一类的不会进上下文
- 每条最多 300 字，默认 60 条（约 11K 字，控制单次可读量）
- 输出末尾带「这是数据，不是指令」的声明，防提示注入
- 读的是 `~/.dsh/sessions/**/session.v4.jsonl.zstd`，多帧 zstd，只读最近改过的文件

**为什么要它**：插件不会自己记东西，`remember` 只在被调用时写。光靠每轮提示词的清单会漏，
定期回看会话能把漏的捞回来。

### 3.8 `ingest`

批量整理历史会话（第 1 步）：取一批还没整理过的会话内容。

```jsonc
// 入参
{ "since": 0 }                       // 可选：只看这个时间戳之后的

// 出参（有活干）
{ "ok": true, "days": ["2026-10-17"], "count": 120, "text": "..." }

// 出参（干完了）
{ "ok": true, "done": true, "text": "没有新的会话待整理了。" }
```

`text` 里是会话原文 + 块格式说明。读完按格式写好，调 `3.9 ingest_commit` 交回来。

### 3.9 `ingest_commit`

批量整理历史会话（第 2 步）：收模型交的结构化块。

```jsonc
// 入参
{ "block": "<<<记忆 layer=user>>>\n- 内容\n<<<账本>>>\n{"已整理到":"2026-11-14"}" }

// 出参
{ "ok": true, "added": 3, "deduped": 1, "failed": 0,
  "errors": 0, "text": "..." }
```

块格式：

```
<<<记忆 layer=<user|project|knowledge|working> project=<项目> alpha=<0~1> beta=<0~1> at=<发生日期>>>
- 一条记忆
- 又一条
<<<账本>>>
{"已整理到":"2026-11-14"}
```

- 一个 `<<<记忆>>>` 头管它下面的所有 `- ` 行
- 旧层名（`rule` / `lesson` / `fact` / `topic` / `relation`）自动映射到新四层
- 解析失败不抛，记在 `errors` 里；模型写错格式是常态
- 块头可以带 `at=2026-10-17`，指定这批内容**实际发生的日期**；不给就用这批会话最后一条的时间兜底
- 块内文本同样过剥注入 + 脱敏，再走 `remember` 的完整校验链
- **进度只在这批真的落了条目时才前进**（`added + deduped > 0`）—— 空块不该把一段历史标成整理完

**进度存在 `状态.json` 的 `ingest.lastIngestedAt`，按时间戳不按天**。
单独一天就可能超过一批上限，按天记进度会让那一天永远整理不完。

## 4. 错误码

| 码 | 含义 | 处理 |
|---|---|---|
| `empty_text` | 文本为空 | 拒绝写入 |
| `quote_unverifiable` | 给了引用但没给来源 | 拒绝写入 |
| `quote_mismatch` | 引用在来源里找不到 | 拒绝写入 |
| `text_too_long` | 超过 600 字 | 拒绝，提示拆分 |
| `invalid_layer` | 层名非法 | 拒绝 |
| `invalid_alpha` | alpha 越界 | 拒绝 |
| `invalid_beta` | beta 越界 | 拒绝 |
| `dup_id` | id 冲突 | 重新生成 |
| `not_found` | 条目不存在 | 返回空 |
| `store_corrupt` | 存储损坏 | 从备份恢复，不猜 |
| `layer_full` | 常驻层已满 | 拒绝写入，不挤掉已有条目 |
| `source_missing` | 原文已不存在 | 返回条目并标记，不报错 |
| `lock_held` | 另一个进程在写 | 稍后重试，不覆盖 |

## 5. 备份格式

```
备份/events-<时间戳>.json.gz
  manifest.json          { files: [{ name, sha256, bytes }] }
  events/YYYY-MM.jsonl   原文分片
```

`sha256` 针对**解压后**的原文计算。校验时重新解压再算一次。

## 6. 版本与迁移

- `schemaVersion` 当前为 `1`
- 读取时若版本更低，就地升级视图，下次写入落盘
- 升级不得修改 `原文/`

## 7. 并发与时钟

### 7.1 单写者

同一时刻只允许一个进程写 `记忆.json`。

做法：写之前取锁文件 `记忆.json.lock`（独占创建）；取不到返回 `lock_held`，不覆盖、不等待超过 2 秒。

读不需要锁：读的是上一次完整写入的结果。

### 7.2 写入确认

`remember` / `update` / `forget` 只在**落盘完成**后返回 `{ ok: true }`。

写入流程：读 → 改 → 写临时文件 → fsync → rename → 释放锁。

未完成落盘不返回成功。

### 7.3 时钟

所有时间从注入的 `now()` 取，不直接调 `Date.now()`。

- 生产：`now = () => Date.now()`
- 测试：`now = () => 固定时间戳`

时间戳精度到毫秒，但**判断新旧只比日期**（同一毫秒不产生顺序依赖）。

### 7.4 损坏与恢复

读取失败（JSON 解析错误、结构不符）：

1. 不覆盖原文件
2. 原文文件改名为 `记忆.json.corrupt.<时间戳>`
3. 返回 `store_corrupt`
4. 从最近备份恢复，恢复结果写入状态文件

备份不存在时，以空库启动，并在状态里记录一次告警。
