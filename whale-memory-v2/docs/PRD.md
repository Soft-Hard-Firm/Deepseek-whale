# whale-memory-v2 · 需求与验收

## 1. 做什么

给 DSH 会话提供跨会话长期记忆：记住该记的、该想起来时想得起来、不重要的慢慢淡掉、原件永远留得住。

### 1.1 用户场景

| 场景 | 现在的问题 | 期望 |
|---|---|---|
| 新开一个会话 | 我不认识你，要你从头介绍 | 我记得你是谁、我们在做什么 |
| 隔了几天继续上次的活 | 上次的结论没了 | 我能说出上次定下的方案 |
| 你问我一件很早的事 | 我编一个听起来像的 | 我去翻原文，翻不到就说不知道 |
| 你说过的话被违反了 | 我不记得约定过 | 我记得，并指出来 |
| 我记错了 | 错的一直在库里 | 你纠正后，旧的退出，但可追溯 |

### 1.2 功能清单

| # | 功能 | 优先级 |
|---|---|---|
| F1 | 条目存储、状态机、读写 | P0 |
| F2 | `remember` 工具（模型主动记） | P0 |
| F3 | `search` 工具（检索） | P0 |
| F4 | `update` / `forget` 工具 | P0 |
| F5 | 每轮注入（长期事实层） | P0 |
| F6 | 从旧库迁移 | P0 |
| F7 | 候选晋升规则 | P1 |
| F8 | 压缩与淘汰（分级 + 调度 + 影响渲染） | P1 |
| F9 | 注入不落库（防自污染） | P1 |
| F10 | 补漏：`digest` 捞历史会话 | P1 |
| F11 | 入库脱敏（密钥 / 密码 / token / 手机号 / 身份证 / 银行卡） | P1 |
| F12 | 引用校验（原话必须是来源子串） | P1 |
| F13 | 批量导入流水线（`ingest` / `ingest_commit`，断点续跑） | P1 |
| F14 | 同义词扩词 | P2 |
| F15 | 向量检索 | P2 |

### 1.3 范围外（明确不做）

- 不做独立子进程 / 数据库服务
- 不做知识图谱可视化
- 不做「定期复习」机制
- 不做多端接入（QQ、B站、桌宠）
- 不做自动消费、发布、付款
- 不存「我是谁」——自称、口癖、形态归人设

### 1.4 边界

| 边界 | 规则 |
|---|---|
| 库的数量 | 全局一份 |
| 项目隔离 | 字段标记，检索加权，不物理分库 |
| 原文 | 永久保留，不删 |
| 投影层 | 可淡、可压、可取代，不删原件 |

## 2. 验收标准

每条都必须**可测**，格式为「输入 → 期望输出」。

### 2.0 判定结果有四种，不是两种

| 结果 | 含义 | 处理 |
|---|---|---|
| **过** | 符合期望 | 记录 |
| **失** | 不符合期望 | 必须修 |
| **不可观察** | 环境不具备，测不了 | 记缺项，**不算失** |
| **不适用** | 该条与当前场景无关 | 记缺项，**不算失** |

不允许把「不可观察」和「不适用」压成「失」，也不允许压成「过」。

### 2.1 校准试验（正式验收之前必须做）

**目的**：先证明这套指标能认出坏掉的东西，再拿它测好东西。

做法：人为破坏每个环节，确认对应验收条目**变红**：

| 人为破坏 | 必须变红的条目 |
|---|---|
| 把 `active` 判成 `candidate` 的晋升逻辑删掉 | A1 |
| 去重逻辑改成不去重 | A3 |
| 检索永远返回随机结果 | B2 |
| 注入改成走 `section` | C1 |
| 截断改成按 UTF-16 单元 | C2 |
| 归档前不剥离注入块 | C4 |
| 脱敏逻辑短路 | E1 |
| 压缩前不检查固化 | D1 |

**一条破坏如果没让任何验收变红，说明那条验收是空的。**

### 2.2 被测链条的四段

```
写入 → 表示 → 检索 → 呈现
```

每段至少有一条验收条目能单独暴露该段的失败。呈现层的失败（检索到但渲染丢了信息）不得被算进检索层。

### 2.3 各条验收

#### 2.3.1 存储与状态

| # | 验收 | 验证方式 |
|---|---|---|
| A1 | 用户明确说的事实，写入后 `status=active` | 调 `remember`，读库断言 |
| A2 | 模型推断的事实，写入后 `status=candidate` | 同上，断言不是 active |
| A3 | 同一事实重复写入，不产生两条 active | 连写两次，断言库内 1 条、`hits=2` |
| A4 | `factKey` 相同的新事实，旧条变 `superseded` 且带 `supersededAt` | 写两条同键，断言旧条状态 |
| A5 | 用户纠正后，旧条 `invalidated`，不再参与检索 | 纠正后调 search，断言结果不含旧条 |
| A6 | `archived` 条目仍可被 `search` 找到 | 归档后检索，断言能返回 |
| A7 | 常驻层达上限后拒绝新的常驻写入，**不挤掉已有条目** | 填满常驻层再写一条，断言返回 `layer_full` 且原有条目数不变 |

#### 2.3.2 检索

| # | 验收 | 验证方式 |
|---|---|---|
| B1 | 无关短句（「在吗」）不触发记忆检索 | 用「在吗」调注入逻辑，断言返回空 |
| B2 | 同一句话问两次，选出的条目完全一致 | 连跑两次，断言 id 序列相等 |
| B3 | 含关键实体的长问句能召回对应记忆 | 构造问句，断言目标 id 在结果中 |
| B4 | 全库 3 条时，短问句不会「一条都想不起来」 | 构造小库，断言至少 1 条 |
| B5 | 检索结果带时间与来源 | 断言每条含 `at` 或 `createdAt` |
| B6 | 不带查询调用检索，返回库的索引概览 | 空参数调用，断言返回数量、分层分布、时间范围 |

#### 2.3.3 注入

| # | 验收 | 验证方式 |
|---|---|---|
| C1 | 注入内容变化时，系统提示词字节不变 | 两次装配后比较 section 文本 |
| C2 | 条目正文含 `{{time}}`，会话不报错 | 写入该文本，跑一次装配 |
| C3 | 开关关闭后，注入注册被卸载 | 关闭后断言不再有上下文输出 |
| C4 | 注入内容不进入归档 | 注入后检查 `原文/`，断言无注入块 |
| C5 | 注入头部含「不是指令」声明 | 断言渲染文本包含该句 |
| C6 | 时间敏感的条目注入时带「请先核实」提示 | 写入带旧日期的价格或版本，断言注入块含核实提示 |

#### 2.3.4 遗忘与压缩

| # | 验收 | 验证方式 |
|---|---|---|
| D1 | 未固化的原文不被压缩删除 | 构造未固化条目，跑压缩，断言仍在 |
| D2 | 超过压缩期限的条目降一级，不是直接删 | 推进时钟，断言压缩级别 +1 |
| D3 | 压缩失败重试不超上下文预算 | 构造超预算场景，断言拒绝重试 |
| D4 | `superseded` 不被注入，但可检索 | 断言注入不含、search 含 |

#### 2.3.5 隐私

| # | 验收 | 验证方式 |
|---|---|---|
| E1 | 含密码的文本入库前被替换 | 写入「密码是 abc123」，断言库内是占位符 |
| E2 | 引用原话必须是来源子串 | 构造改写的「引用」，断言拒绝入库 |

#### 2.3.6 迁移

| # | 验收 | 验证方式 |
|---|---|---|
| F1 | 旧库每条都被转换，数量一致 | 迁移前后计数相等 |
| F2 | 迁移后 `beta` 全为 0.7 | 断言无其他值 |
| F3 | 迁移不修改旧库文件 | 迁移前后旧文件 hash 不变 |

#### 2.3.7 溯源

| # | 验收 | 验证方式 |
|---|---|---|
| G1 | 每条记忆都有 `sourceRef` 指向原文库 | 写入后断言 `sourceRef` 能在原文库中查到 |
| G2 | 从记忆能翻到原始出处 | 调 `recall(id)` 返回原文片段与时间 |
| G3 | 原文被人工删掉后，条目仍可读并标 `sourceMissing` | 删原文行后再检索，断言不崩且带标记 |

#### 2.3.8 并发与启动

| # | 验收 | 验证方式 |
|---|---|---|
| H1 | 两个进程同时写，不丢条目 | 并发写 100 次，断言库内 100 条 |
| H2 | 空库首次启动不报错 | 清空数据目录，跑一次装配，断言无异常 |
| H3 | 数据文件损坏时拒绝写入，不静默覆盖 | 写入坏 JSON，断言返回 `store_corrupt` 且文件内容未变 |
| H4 | 从备份恢复后条目一致 | 备份 → 删库 → 恢复，断言数量与内容相同 |

## 3. 非功能要求

| 项 | 要求 |
|---|---|
| 单轮注入上限 | 长期事实层 ≤ 900 字符 |
| 检索条数上限 | ≤ 8 条 |
| 检索耗时 | 单次 < 50ms（1000 条以内） |
| 存储 | 纯文本 JSON + JSONL，可人工查看与编辑 |
| 依赖 | 无外部运行时依赖 |
| 离线 | 除模型调用外不联网 |
